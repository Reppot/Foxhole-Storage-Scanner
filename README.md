# Foxhole Storage Scanner (RUS)

[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
![Platform](https://img.shields.io/badge/platform-Windows-lightgrey)
![Python](https://img.shields.io/badge/python-3.10%2B-blue)
![Status](https://img.shields.io/badge/status-активная%20разработка-brightgreen)

Инструмент, который сам следит за твоими складами в **Foxhole** и красиво
присылает их содержимое в **Discord** — без ручного скриншотинга и
перепечатывания списков. Работает поверх движка [`xurxogr/foxhole-stockpiles`](https://github.com/xurxogr/foxhole-stockpiles)
(сканирование), плюс собственный модуль `relay.py`, который превращает
результат в аккуратную картинку с русским текстом в Discord.

## 1. Установка и запуск «с нуля»

> Этот раздел рассчитан на то, что ты **вообще не программист** и видишь
> командную строку первый раз в жизни. Повторяй шаги по порядку, ничего
> не пропуская.

### Шаг 1 — Установи Python

1. Открой [python.org/downloads](https://www.python.org/downloads/) и
   скачай последнюю версию Python для Windows.
2. Запусти установщик.

   > **Важно:** на первом экране установки обязательно поставь галочку
   > **"Add python.exe to PATH"** внизу окна — без неё ничего дальше не
   > заработает.

3. Нажми **"Install Now"** и дождись завершения.
4. Проверь, что всё встало: открой командную строку (`Win` → введи `cmd`
   → `Enter`) и напиши:
   ```cmd
   python --version
   ```
   Если в ответ показалась версия (например `Python 3.12.4`) — всё
   хорошо, иди дальше. Если написано *"команда не найдена"* —
   переустанови Python, не забыв галочку из пункта 2.

### Шаг 2 — Скачай сам проект

1. Скачай проект как ZIP-архив (кнопка **Code → Download ZIP** на
   странице репозитория) и распакуй его в удобное место, например
   `D:\Games\foxhole-stockpiles-main`.
2. Внутри должна появиться папка со множеством файлов и подпапок
   (`relay.py`, `fs.exe`, `Icons Foxhole` и т.д.) — если видишь их, всё
   распаковалось верно.

### Шаг 3 — Установи зависимости Python

1. Открой командную строку и перейди в папку проекта (замени путь на
   свой):
   ```cmd
   cd D:\Games\foxhole-stockpiles-main
   ```
2. Установи нужные библиотеки одной командой:
   ```cmd
   pip install flask requests pillow
   ```
   Если Windows пишет *"pip не является внутренней командой"* —
   используй вместо `pip` вызов `py -m pip`:
   ```cmd
   py -m pip install flask requests pillow
   ```

### Шаг 4 — Создай Discord-вебхук

1. В Discord зайди в настройки нужного канала →
   **Интеграции → Вебхуки → Создать вебхук**.
2. Дай вебхуку имя (например «Склады»), нажми **«Копировать URL
   вебхука»**. Получится ссылка вида:
   ```
   https://discord.com/api/webhooks/1234567890/AbCdEf...
   ```
3. Сохрани эту ссылку куда-нибудь — она понадобится на следующем шаге.

   > **Не показывай эту ссылку никому** — по ней любой человек сможет
   > слать сообщения в твой канал.

### Шаг 5 — Запусти сервер-транслятор (`relay.py`)

1. В той же командной строке (папка проекта) выполни две команды
   подряд, подставив свою ссылку из шага 4:
   ```cmd
   set DISCORD_WEBHOOK_URL=https://discord.com/api/webhooks/твоя_ссылка
   python relay.py
   ```
2. Если всё правильно, в окне появится строка вида
   `Relay запущен на http://127.0.0.1:5001/relay`.

   > **Это окно нельзя закрывать**, пока хочешь получать склады в
   > Discord. Просто сверни его.

3. Если написано `DISCORD_WEBHOOK_URL не задан` — значит команда `set`
   не выполнилась или ты открыл новое окно cmd. Повтори шаг 1 из этого
   блока в том же самом окне, откуда запускаешь `python relay.py`.

### Шаг 6 — Настрой сканер (`fs.exe`)

1. Запусти `fs.exe` из папки проекта.
2. Открой **Settings → General** и поставь язык **Russian**.
3. Открой **Настройки → Вывод (Output)**, включи **Webhook** и укажи
   адрес (тот самый, что написал `relay.py` в шаге 5):
   ```
   http://127.0.0.1:5001/relay
   ```
   Поле авторизации (`auth_type`) оставь пустым.
4. Открой **Настройки → Вход (Input)** и выбери способ, которым сканер
   будет получать данные о складе — подробности какой выбрать смотри в
   разделе [«Возможности»](#2-возможности-проекта-от-главных-к-второстепенным) ниже.
5. Отсканируй склад любым выбранным способом — в окне `relay.py` должны
   появиться логи, а в Discord-канале — картинка со списком предметов.

> **Если что-то не заработало** — не паникуй, почти все типичные
> проблемы разобраны в разделе [FAQ](#5-faq-вопросы-и-ответы) дальше в
> этом README. Особенно если видишь в консоли `DISCORD_WEBHOOK_URL не
> задан`, `icon_missing` или `UNMAPPED_ITEM` — это штатные, разбираемые
> ситуации, а не поломка.

## 2. Возможности проекта (от главных к второстепенным)

### 2.1. Три независимых способа получить данные о складе

Не нужно вручную печатать содержимое склада — сканер сам его считывает
одним из трёх способов (можно включить сразу несколько):

| Способ | Как работает | Точность / надёжность |
|---|---|---|
| **OCR / Live Capture** | По горячей клавише (по умолчанию `F9`) программа делает скриншот активного окна игры и распознаёт предметы и количества движком `fs-ocr`. Можно также скормить готовый файл скриншота вручную. | 99.99% по внутренним тестам проекта (27 538 предметов), 1–2 сек/кадр, разрешения от 1280×1024 до 4K |
| **Clipboard Scanning** | Нажимаешь в игре кнопку **"Copy to Clipboard"** в окне склада — игра копирует точный текстовый список в буфер обмена, программа мгновенно его подхватывает и разбирает по `data/catalog.json`. | Ошибок распознавания в принципе быть не может — это готовый текст, не картинка |
| **SAV Parsing** | Читает файл сохранения `MapData.sav` напрямую (формат разбирался вручную — см. `ChatExportforDEV`). Обрабатывает только склады, закреплённые ("pinned") на внутриигровой карте. Есть режим слежения за файлом. | Ограничено только закреплёнными складами |

### 2.2. `relay.py` — красивая доставка в Discord

Сырой JSON от сканера нечитаем для игроков, поэтому `relay.py`:

- превращает список предметов в картинку (иконка + русское название +
  количество) на фирменном фоне;
- **автоматически режет длинный список на несколько картинок**, если
  предметов много — каждая уходит отдельным сообщением в Discord с
  номером «Стр. X/Y», чтобы не получить одну нечитаемую «простыню» на
  несколько экранов;
- шлёт итог через Discord webhook, без необходимости никаких прав бота.

Поведение настраивается переменными окружения перед запуском:

| Переменная | По умолчанию | За что отвечает |
|---|---|---|
| `DISCORD_WEBHOOK_URL` | — (обязательна) | Адрес вебхука Discord-канала |
| `MAX_ROWS_PER_IMAGE` | `12` | Сколько предметов помещается на одну картинку до переноса на следующую |
| `DISCORD_SEND_DELAY` | `0.4` | Пауза (в секундах) между отправкой сообщений — увеличь при рейт-лимите Discord |

### 2.3. Многоуровневая система русской локализации

Название предмета ищется по коду сразу в нескольких источниках —
**первое найденное значение побеждает**:

1. Ручные правки прямо в `relay.py` *(наивысший приоритет)*
2. `item_codes.py` — твой личный словарь код → русское название
3. `foxhole_stockpiles/i18n/translations/ru.json` — базовый перевод из
   самого движка сканера

Это позволяет не трогать движок сканера вообще, а все свои правки
держать в одном отдельном файле (`item_codes.py`).

### 2.4. Автоматический подбор иконок

Иконка для предмета ищется по коду в несколько шагов: сначала явные
ручные записи (`ITEM_ICON_FILES` в `relay.py`), затем точное совпадение
имени файла в папке `Icons Foxhole` (рекурсивно, по всем подпапкам) с
кодом предмета, и в конце — иконки, скачанные с Foxhole Wiki
(`wiki_icon_fixes.py`), для предметов без своей вырезанной иконки.

### 2.5. Диагностика «битых»/неизвестных предметов

Если игра обновилась и появился новый предмет, для которого ещё нет ни
перевода, ни иконки — это не ломает работу, а:

- пишется в консоль строкой с тегом `UNMAPPED_ITEM`;
- копится в файле `unmapped_items.log` (без дублей);
- доступно на `GET http://127.0.0.1:5001/unmapped` как JSON;
- после каждого запроса печатается сводка `=== НЕРАСПОЗНАННЫЕ ПРЕДМЕТЫ ===`
  — удобно копировать целиком для разбора.

### 2.6. Инструменты для дозаполнения словарей

<details>
<summary>Для тех, кто дорабатывает проект (нажми, чтобы раскрыть)</summary>

- `generate_mapping.py` — сопоставляет `data/catalog.json` с папкой
  иконок автоматически (точное имя → без регистра/разделителей →
  нечёткое сравнение через `difflib`).
- `list_wiki_icons.py` / `match_wiki_icons.py` — то же самое, но для
  иконок, скачанных с Foxhole Wiki: строит список файлов и сопоставляет
  их с уже известными кодами предметов.

</details>

### 2.7. Графический интерфейс и CLI движка сканера

`fs.exe` — это не только консоль: есть полноценный GUI (настройки,
сборщик баз данных из файлов игры, визуализатор базы, трей-иконка) и
командная строка (`fs scan`, `fs clip`, `fs sav`, `fs gui`) — подробности
в `docs/advanced.md`.

### 2.8. Прочее

- Поддержка Docker-развёртывания (`docker-build.sh`, `.dockerignore`)

- Мультиязычный интерфейс сканера (`fs_tools/i18n/translations` — de,
  en, es, fr, pt, ru, zh)

### Как эти файлы работают вместе (коротко)

```
fs.exe (сканирует) → POST JSON на http://127.0.0.1:5001/relay
                    → relay.py ищет перевод: relay.py → item_codes.py → ru.json
                    → relay.py ищет иконку: ITEM_ICON_FILES → Icons Foxhole/ → wiki_icon_fixes.py
                    → рендер картинки на фоне scr/gray-background.jpg
                    → отправка в Discord через webhook
```

Файлы `generate_mapping.py`, `list_wiki_icons.py`, `match_wiki_icons.py`
— это не часть рабочего процесса, а **разовые утилиты для дозаполнения
словарей**: запускаешь, когда появились новые непереведённые предметы
или новая партия иконок, и получаешь готовый файл-словарь, который
потом просто подключается в `relay.py` / `item_codes.py`.

## 4. Планы на будущее (что можно добавить)

> Ничего из этого не реализовано сейчас — просто идеи, с которых можно
> начать, если будет желание продолжать проект.

- [ ] **OCR-распознавание «Срок действия»** — научить сканер читать со
      скриншота строку вида `Срок действия: 01d12h` у Reserve Stockpile
      и прокидывать её в отчёт. Это значение не хранится ни в одном
      локальном файле игры (проверено разбором `MapData.sav`) —
      единственный легальный способ получить его — распознавание с
      картинки, аналогично тому, как уже распознаются названия
      предметов и количества.
- [ ] **Привязка координат склада к названию города/POI.** Сейчас в
      отчёт попадают только сырые нормализованные координаты (X/Y от 0
      до 1 внутри гекса). Нужен отдельный справочник координат
      городов/точек интереса по каждому гексу — тогда можно будет
      находить ближайший город по формуле расстояния.
- [ ] **Автоматическое обновление словарей при выходе патча Foxhole** —
      сейчас `generate_mapping.py` / `match_wiki_icons.py` запускаются
      вручную. Можно сделать это отдельной командой или встроить
      проверку прямо в `relay.py` при старте.
- [ ] **Один общий скрипт вместо трёх** (`list_wiki_icons.py` +
      `match_wiki_icons.py` + `generate_mapping.py`) — объединить в
      одну команду с понятными флагами.
- [ ] **Web-панель или Discord-команда** для просмотра
      `unmapped_items.log` и истории складов без необходимости лезть в
      файлы на диске.
- [ ] **Уведомление о смене владельца/захвате склада**, если такая
      информация станет доступна через один из трёх методов сбора
      данных.
- [ ] **Docker-образ конкретно под `relay.py`** (сейчас
      Docker-конфигурация в проекте относится к апстрим-движку
      `fs.exe`, не к `relay.py`).

## 5. FAQ (вопросы и ответы)

#### В логе вижу `WARNING UNMAPPED_ITEM code=... name_missing=True/icon_missing=True`. Что это?

Штатное сообщение о новом предмете, для которого чего-то не хватает:

- `name_missing=True` — нет перевода. Добавь строку в `item_codes.py`,
  например:
  ```python
  'EmplacedHeavyArtilleryW': 'Стационарная тяжелая артиллерия',
  ```
- `icon_missing=True` — нет иконки. Вырежи иконку из игры (или найди на
  Foxhole Wiki), положи в `Icons Foxhole/` и, если имя файла не
  совпадает с кодом предмета один в один, добавь явную запись в
  `ITEM_ICON_FILES` внутри `relay.py`.
- Если рядом видно `Discord ответил: 200` — сообщение всё равно
  успешно дошло до Discord, просто с автоматически «причёсанным»
  названием или пустым квадратом вместо иконки.

#### Как отследить и исправить непереведённые/безымянные предметы массово, а не по одному?

Три инструмента для этого:

1. `unmapped_items.log` — копится автоматически, без дублей. Проверяй
   его после каждого патча игры.
2. Консоль `relay.py` — там же в реальном времени видно HTTP-статусы
   ответов Discord (`200` — доставлено, `400` — неверный формат,
   `404` — неверный/удалённый вебхук).
3. `generate_mapping.py` / `match_wiki_icons.py` — сопоставляют сразу
   пачку кодов с файлами иконок автоматически, не по одному вручную.

#### Все предметы отмечены как `icon_missing`, хотя картинки точно лежат в папке.

Почти всегда это неверный путь до папки с иконками внутри `relay.py`.
Убедись, что там используется путь, посчитанный относительно самого
скрипта (`os.path.dirname(os.path.abspath(__file__))`), а не жёстко
прописанный путь вроде `D:\...\Foxhole-Storage\...` — такой путь
ломается при любом переносе или переименовании папки проекта.

#### `pip install` пишет, что команда не найдена.

Python не добавлен в PATH. Либо переустанови Python, отметив галочку
**"Add python.exe to PATH"**, либо временно используй:
```cmd
py -m pip install flask requests pillow
```

#### Как не слить токен Discord-вебхука в открытый доступ (например, на GitHub)?

Никогда не вписывай ссылку вебхука в файлы проекта. `relay.py`
намеренно читает её только из переменной окружения — передавай её
командой `set DISCORD_WEBHOOK_URL=...` прямо перед запуском, каждый раз
заново в новом окне командной строки. После закрытия окна cmd значение
нигде не остаётся.

#### `relay.py` пишет «DISCORD_WEBHOOK_URL не задан» и не отправляет ничего.

Значит команда `set DISCORD_WEBHOOK_URL=...` либо не выполнялась в этом
окне cmd, либо была выполнена в другом окне. Переменные окружения не
общие между разными окнами консоли — выполняй `set` и `python relay.py`
в одном и том же окне, одно за другим.

#### Один и тот же предмет иногда виден под двумя разными кодами (например `LiquidContainer` и `ZhidkostnyyKonteyner`) — это баг?

Нет, это ожидаемо. У проекта два независимых источника кодов: настоящие
внутренние коды игры (приходят через OCR/webhook) и синтетические
коды, сгенерированные транслитерацией названия (нужны для метода
Clipboard Scanning, у которого нет доступа к настоящему коду). Оба
варианта могут существовать одновременно как разные ключи одного
словаря — это не конфликт, а поддержка сразу двух методов сбора
данных.

#### Склад с большим количеством предметов приходит как много отдельных сообщений в Discord — можно сделать картинки покрупнее/пореже?

Да, через переменные окружения перед запуском `relay.py` (см. таблицу
в разделе [2.2](#22-relaypy--красивая-доставка-в-discord)):
```cmd
set MAX_ROWS_PER_IMAGE=20
set DISCORD_SEND_DELAY=0.6
```

#### Можно ли достать координаты города или таймер «Срок действия» склада откуда-то ещё, кроме OCR?

Нет — оба варианта проверены разбором файла `MapData.sav` вручную:
координаты города там попросту не хранятся (только нормализованные X/Y
внутри гекса), а «Срок действия» вычисляется сервером игры на лету и
никогда не кэшируется на диске клиента. Единственный легальный путь —
распознавание текста со скриншота, см. [раздел 4](#4-планы-на-будущее-что-можно-добавить).
